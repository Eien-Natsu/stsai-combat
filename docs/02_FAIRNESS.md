# 信息边界与可复现性

## 可见与不可见

可以使用当前手牌、公开牌区的卡牌多重集、能量／HP／格挡、敌人当前合法可见意图、公开状态／计数、玩家此前实际见到的历史。被合法效果确定的牌顶可放入 `known_top`。不能因为接口没有当前手牌顺序限制，就导出真实抽牌堆排列或随机数种子。

黑名单检查只是回归防线，**不是安全证明**：把 rng 改名叫别的字段仍能绕过黑名单。因此导出器采用白名单构造，而不是删除几个字段后把对象整体序列化。动作“提示伤害”只能由当前可见状态计算，不能调用带未来随机结果的动作执行。

## 三个隔离层

1. observation：白名单、未知抽牌排序、剔除 UUID／uniqueId／指针／seed／RNG。已知牌顶是独立字段。
2. search：节点分支只依赖观察历史；sampler 使用 agent 自己的种子，不能借用真实未来随机流。要求根观察不变、动作集一致、采样不修改真实环境。
内部决策随机种子按 agent / split / episode index 的独立命名空间生成，不使用真实 episode_seed 作为搜索或行为采样的输入。

3. training：网络编码只允许公开实体；backend 与 split 必须一致；测试数据拒绝用于训练和 failure mining。

## 本版 native 的具体限制

对 Cultist 和 Jaw Worm 的 pilot，保留已经发生的状态／动作历史，替换六类未来随机生成器，先规范排序再打乱未知抽牌。`bc.seed` 不传给策略。**这是独立随机流近似**，不是根据原版 seed 耦合关系计算的精确贝叶斯后验，也不是通用敌人采样器。

上游 BattleContext 在初始化时多条流由同一 seed／floor 初始化。因此“独立重置”会改写流间相关性。当前策略不利用真实未来，但这仍然可能产生模型偏差；不能用“没泄露 seed”推断“随机分布完全正确”。进一步需要维护从合法观察历史出发的粒子后验、按原版流相关结构推进并重采样，或者明确采用公平但近似的独立机会模型并衡量误差。

其它敌人可能预先保存未来伤害、目标或状态在 miscInfo 中；直接复制就可能泄露或影响模拟结果。每扩展一种敌人都要审计字段、测试同一公开历史下不同隐藏状态的搜索不变性。Runic Dome／隐藏意图的场景当前拒绝，不导出原游戏内部仍然知道的意图。

## 可复现等级

相同代码、相同引擎 revision、相同配置、相同场景／搜索 seed 的 reference CPU 搜索可重复。PyTorch 跨设备／版本数值不保证逐位一致；GPU 训练也未强制全局 deterministic 算法。checkpoint 保存参数、优化器、随机状态、步数；**恢复部分 epoch 会从该 epoch 开头重新读样本，不是精确数据游标恢复**。

收集中的同一 episode 可跳过已完成文件；前提是数据目录 fingerprint 一致。不能同时启动两个收集作业写同一目录与 index 区间。不同训练配置／teacher／目标必须新目录。审计完整性建议为 replay 文件另建 SHA256 清单；现有 manifest 是配置来源记录，不是防恶意篡改的密码学数据证明。

验证集用于调参，最终测试 manifest 在选定模型后生成，默认不可覆盖。运行参数和模型 hash 均须保存。对最终测试的失败样本再训练后，需要新的最终盲测集。
