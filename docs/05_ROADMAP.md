# 从有限 pilot 扩展到真正的战斗 AI

下表是接手 AI 的实施工单，不是已实现的能力声明。优先级按依赖排序，先保证正确性再追求强度。

| 工单 | 实施内容 | 验收证据 |
|---|---|---|
| P0 编译与一致性 | 固定上游，修 native，完成 G2/G3 | 构建、原版轨迹、规则差分、公平性测试 |
| P1 单卡选择 | True Grit、Armaments、Headbutt、Warcry、Dual Wield 等 | 每种选择阶段合法动作完整；恢复搜索无状态错配 |
| P2 多选／顺序选择 | 以真实规则需要多选的卡／药水为单位实现选择状态机 | 0..k 合法子集完整；不把“空选择”当唯一动作 |
| P3 状态与生成卡 | 抽牌／消耗协同、腐化／黑拥／无惧疼痛、状态牌、临时费用 | 效果链／队列边界／多次触发与原版一致 |
| P4 药水 | 使用、丢弃、目标、选牌药水、槽位、公开存量 | 动作覆盖、资源价值上下文、原版同轨迹验证 |
| P5 遗物 | 次数计数、每回合／战斗触发、能量／抽牌／回血 | 导出所有影响未来的公开计数，隐藏意图场景单独处理 |
| P6 更多敌人 | 多敌人、复活、分裂、精英、Boss、Heart | 每个敌人的隐藏字段审计及信念采样测试 |
| P7 实机搜索 | 公开历史到 native belief root 的恢复接口 | 相同公开历史、不同隐藏真值时动作统计不变 |
| P8 强化与性能 | 搜索批处理、C++ 热路径、叶值校准、宏动作／树复用 | 等预算实战提高；p95 延迟与内存下降 |

上表列举的卡名描述工作主题，不代表它们都使用同一种选择类型。例如 Fiend Fire 本身是整手消耗动作，Exhume 是消耗堆单选；每张卡必须以真实规则决定动作模式，不能照工单标题机械分类。

## 搜索的关键扩展

上游 `Action::enumerateMultiCardSelectActions` 中某些多选分支只返回空选择。不能照搬这一枚举器然后声称完整策略空间。手牌上限范围内优先完整枚举合法集合；分支过大可 progressive widening，但必须保留正确的可达性和拒绝非法组合。是否选择后立即确认、选择顺序是否影响结果，以具体卡／药水阶段为准。

`known_top` 当前 reference 可测试，但 native pilot 没有合法操纵牌顶的卡，所以 native 为空。支持 Warcry／Headbutt 后必须在重采样中保留玩家已知牌顶约束，并在真实环境新增信息后更新信念。不能为了“公平”把合法已知信息也全部丢掉。

## 数据与课程

先用受控卡组生成器覆盖费用／伤害／格挡／力量；再加入真实玩家合法战斗前快照，而不从存档泄露隐藏未来。初始分布记录卡组、HP、敌人、遗物、药水、难度和捕获策略；它决定评测含义。把重复／近重复的整场快照按组划分 train/val/test，不能只随机分决策行。

native 首版四类卡组都混合两种敌人；增加低 HP、弱卡组、缺能量和罕见状态，避免教师几乎全胜、价值头没有死亡样本。难样本过采样要有权重／分布报告，最终强度按预先约定的目标分布计算。

先记录前 16 局的状态数、耗时、文件体积与搜索 cutoff，再决定 128→256→1,024→更大规模。没有测量前不填写样本／秒和训练总时长承诺。单张 5070 是工程约束，不是性能保证。

## 价值校准与风险

outcome head 的 softmax 并非天然校准概率。增加 Brier score、reliability bins、ECE、分难度／卡组／敌人分层评测；只在独立 val 上拟合温度等校准参数。打开 learned leaf value 前先证明高预算搜索或真实执行下的预测误差下降。

如果主要目标改成“尽量不死”，用显式死亡约束或词典序规划，而不是不断任意增加一个死亡罚系数并把结果称为概率最优。全卡池时增加永久资源收益、未来药水保留价格；没有整局上下文时必须报告局内目标限制。

## 性能工作顺序

首先用 profiler 量真实热点：状态复制、JSON/字典构造、legal actions、rollout、网络前向各占多少。现有单节点网络评估可能被 Python 和小 batch 开销限制；GPU 不是越多调用越快。

优先把完整内层 rollout 和状态转移保持在 C++、只在需要网络时批量返回观察；再设计进程间请求批处理的 GPU 推理服务。保留相同算力预算的无网络搜索基准，防止“网络更聪明但总系统更慢”。不要用缩减合法动作集合来伪造吞吐提升。
