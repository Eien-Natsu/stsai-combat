# S2 小结

**结论先说：在固定模型与 500 次更新预算下，把训练战斗从 96 局增加到 384 局，
三个 seed 的效用差方向一致但条件区间跨 0 —— 按预注册规则记为"证据不足"。**
分布拟合确实变好了（KL 更低、与教师实际选择一致率更高），但没有转化为已确认的闭环收益。
两种配置都保留，不补 seed、不换 checkpoint。

下面按第 7 节要求的七个问题逐条回答。

## 1. 冷构建缺失头文件如何修复？哪些环境真正运行？失败日志是否完整？

- **修复**：新增补丁 `0005-CardManager-algorithm-include.patch`，给
  `src/combat/CardManager.cpp` 加一行 `#include <algorithm>`（该文件用 `std::find` 却没包含它）。
  补丁加在原有序列之后，**没有重写 0004，也没有把它伪装成 0004 的一部分**；
  `engine_lock.json`、离线快照 manifest、`audit/patch_reconstruction.json` 都更新为 5 个补丁。
  语义版本一律未动（schema 4 / encoding 5 / loss 2 / sampler `public_history_candidate_sampling/2`）。
- **真正运行的环境**：本机 Debian 12 + **GCC 12.2** + cmake（venv 内）+ Python 3.12.14，
  在**干净克隆**里跑完整链条：补丁序列 → 离线构建 → import → 意图表 → 全量 pytest →
  反事实重放 → 12 条模型 smoke，全部通过（`tests/build_and_test.log.gz`、`tests/junit.xml`）。
- **未在本机运行**：GCC 14.2。review 报的失败发生在 GCC 14.2；"只加这一行头文件即可编译"
  由 review 自己的 `header_only_build.log` 证明，**本机没有 GCC 14，因此没有在本地复现该编译器的失败与修复**。
  另外用 `scripts/scan_std_includes.py` 扫了全部引擎 `.cpp`：补丁后已无"用了 std 算法却没包含
  `<algorithm>`"的文件（vendored 的 json 测试除外，不参与编译）——这是源码扫描，不是可移植性证明。
- **失败日志**：`review/offline_native_build.py` 现在把 configure/build 的**完整命令、退出码、
  stdout/stderr** 写进证据目录（`configure.log`/`build.log`），结构化收据里带
  `configure_command`、`build_command`、`toolchain`（编译器路径与版本）；步骤超时记为 **TIMEOUT**，
  与 FAIL / NOT_RUN 分开，三者都让总退出码非零。

## 2. 是否仅增加 288 个独立训练场景？D96 是否为 D384 真子集？有哪些重复/交集？

- 新增采集**只有一次**：`train` index **96–383**，288 局，2 worker，同一 master_seed 20260916、
  同一教师预算（64 simulations 等全同）、同一 `sample_actions=true`、`max_actions=256`、`iteration=0`，
  不使用学生/网络 prior/leaf value。落在独立目录 `data/s2/add288`，没有往 D96 目录混写。
- **D96 = D384 的真子集**：D96 是 `train` index 0–95，只出现一次；D384 由两个**已校验目录**组合读取
  （`data/s1r/train` + `data/s2/add288`），没有改 collection.json 冒充单一来源。
- **交集**：288 个新 episode 与 D96、V24、DEV_OLD256、DEV_PROBE256 之间
  **相同的 (scenario, episode seed) 对为 0**（逐项比对，见 `data/coverage.json`）；
  "公开开局偶然相同"与"重复 episode"分开计数，两者都不是靠挑 seed 得到的零碰撞。
- **规模**：D96 = 96 局 / 1774 行 / 1331 决策状态；Dadd288 = 288 局 / 5117 行 / 3857 决策状态；
  D384 = 384 局 / **6891 行** / 5188 决策状态；V24 = 24 局 / 330 行 / 247 决策状态。

## 5. 新 probe 的 D384−D96 三个 seed 结果及条件场景区间？

主集合 **DEV_PROBE256**（训练前物化并冻结，master_seed 20260919；本轮首次使用）：

| seed | 配对效用差均值 | 场景 bootstrap 95% | D384 更好/更差/持平 |
|---|---:|---|---|
| 17 | +0.00903 | [−0.0101, +0.0289] | 56 / 62 / 138 |
| 29 | +0.00690 | [−0.0099, +0.0239] | 79 / 41 / 136 |
| 43 | +0.01212 | [−0.0066, +0.0317] | 69 / 39 / 148 |
| **三 seed 平均** | **+0.00935** | 三 seed 均值跨 seed 标准差 0.0026，范围 [+0.0069, +0.0121] | — |
| **联合（每场景先对三 seed 取均值再按场景 bootstrap）** | **+0.00940** | **[−0.0035, +0.0233]** | 下界 < 0 |

- 三个 seed **方向一致（全为正）**，但**联合区间跨 0**，按预注册规则
  （三 seed 同向 + 均值为正 + 条件区间下界 > 0）**不满足** → 记为**证据不足**。
- 区间**条件于实际训练出的这三个 seed**，不覆盖训练随机性；3×256 行不是 768 个独立场景。
- 无截断：4096 场全部完成，保守口径（截断记 0）与"仅完成对"敏感性结果在本题上完全一致。
- **旧开发集 DEV_OLD256（次要诊断）方向相同**：三个 seed +0.0002 / +0.0188 / +0.0186，
  联合 +0.0125，区间 **[−0.0003, +0.0261]**，同样跨 0（差之毫厘）。
  两个集合结论**一致（都跨 0、都为正）**，没有出现"新旧结论相反"的情况。
- **KL 与效用分离**：seed17 与 seed43 的 D384 版 kl_dev 明显低于同 seed 的 D96 版
  （0.10001<0.10869、0.10289<0.10600），seed29 几乎持平（0.11115 vs 0.11106，略高 0.00009）；
  **三个 seed 的教师实际选择一致率都更高**（0.595/0.611/0.599 vs 0.567/0.571/0.567）。
  即：**蒸馏分布拟合改善，但没有转化为已确认的闭环收益**。本轮不追加 DAgger、
  价值审计或新教师目标，也不为显著性补第四个 seed。

  两个既往规则修复；意图表分类（`ENGINE_DERIVED_ONLY` / `UI_SOURCE_VERIFIED`）；
  sampler 的独立随机流 + 候选集均匀先验近似。
- **复用的既有结果**：D96_s17 的 run 与 D96/V24 数据（依据见 `semantic_compatibility.json`：
  0005 只增头文件 + 新构建重放 256 场与 S1R 记录逐场一致）。

## 本轮不是结论的部分

- 不是"更多数据无效"的证明：D384 在 500 步内只被遍历约 2.3 遍，负结果只说明**这个固定预算下**没发现收益。
- 不是原游戏一致性、不是超人类、不是最终 test 结果；`game_differential_verified=false`。
